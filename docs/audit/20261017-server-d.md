## Checked and clean (no finding)

- Bind address / ports: `ports.py` holds the 8940 block only; `single.py` probes `127.0.0.1` with a 0.75 s timeout and a capped body read. No socket is bound in the slice.
- Network: `progress.ProfileClient` is read-only GET with TIMEOUT_S, robots-gated, loopback-only for plain http, userinfo / query / fragment refused in the base URL. No authenticated or write call (ToS floor holds).
- Atomic writes: `store.atomic_write_text`, `settings._atomic_write_bytes` and `portraits._write_archive` all write tmp then replace; `settings.apply` splices text in place and re-checks the result equals the intended doc before writing.
- Path inputs: `portraits.blob` / `image` serve only indexed ids (never a path from the request); screenshot names are allowlisted (`SHOT_NAME_RE`, no `..`, no separators). `settings.valid_dir` refuses control characters and relative paths.
- Unbounded growth: overrides retired (50), prompts (2000), play history (100), portraits archive (30 per character) and shots (200), xpbooks used / added (200), profile history (90 days / 20000 rows), zone_xp (200), pets roster (40), today items (200), tracks (30) are all capped.
- Swallowed exceptions: every broad `except Exception` in the slice is a documented degrade-to-default on an injected feed or listener (never on EW's own write path).
- Game ToS floor: nothing in the slice reads game memory, sends input, touches packets or client files. Portraits read FaceTexture read-only with a short-lived handle and never write there; screenshots are referenced in place.
- Data files: all ASCII / LF, every sourced row carries source + verified, every regex compiles (pinned by the owning modules' load tests). No machine path, account id or email.
