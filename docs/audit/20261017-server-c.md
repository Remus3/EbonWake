| SERVER-C-01 | server/ew/logindays.py:63 | M | `split_minutes` walked one day at a time from `start` and called `datetime.fromtimestamp` on it. A stored play / grind stamp before 1970 (corrupt or hand-typed) raised `OSError [Errno 22]` on Windows inside `LoginDays._load`, so the first-run backfill never completed and every history / events read failed, on every call. A very old (but valid) stamp also looped once per day back to it. Fix: split only the last KEEP_DAYS days before `end`, never below epoch 0. No caller keeps older dates, so the output does not change. | tests/test_logindays.py::test_split_clamps_to_the_kept_window, ::test_backfill_and_open_interval_before_1970_never_break_history | FIXED |
| SERVER-C-02 | server/ew/ocrauto.py:1430 | M | The worker loop's `except Exception: pass` swallowed any failure of a tick (watcher view, an extractor, a store write). The shot was already marked seen, so it was lost silently, and plan 073 health still reported no error. Fix: `_tick()` keeps the worker alive but records `"<Type>: <msg>"` and its time in `_err`, which `health()` already serves. | tests/test_ocr_auto.py::test_worker_tick_failure_is_reported_in_health | FIXED |
